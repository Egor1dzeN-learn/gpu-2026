# gpu_2026

Лабораторные работы по высокопроизводительным вычислениям на CPU (OpenMP, векторизация) и GPU (CUDA).

## 1. Общие положения

### 1.1. Формат данных

Во всех работах используется `float32`. Матрицы хранятся в row-major порядке.
Операции выполняются в постановке `C = A * B`, без транспонирования, батчей, `alpha` и `beta`.

### 1.2. Softmax

Softmax рассматривается построчно. Для матрицы `X` размера `[M x N]` каждая строка
нормализуется независимо. Это соответствует `torch.softmax(x, dim=1)` и `np.softmax(x, axis=1)`.

### 1.3. Условия замеров

Все замеры проводятся на одной аппаратной конфигурации с одинаковыми флагами компиляции.
В отчёте указываются модель CPU/GPU, версии компиляторов и библиотек, число потоков OpenMP.

### 1.4. Метрики производительности

Для каждой лабораторной работы применяются все перечисленные метрики:

- время выполнения `t` (мс);
- GFLOPS;
- GB/s;
- ускорение относительно наивной реализации `S`.

Источники для расчёта:

- <https://en.wikipedia.org/wiki/FLOPS>
- <https://en.wikipedia.org/wiki/Memory_bandwidth>
- <https://en.wikipedia.org/wiki/Speedup>

### 1.5. Отчётность

По каждой лабораторной работе оформляется отдельный отчёт. Отчёты не объединяются,
даже если лабораторные используют общий код или общие формулы. Каждый отчёт самодостаточен.

### 1.6. Требования к отчёту по каждой лабораторной работе

1. **Цель работы.** Одно-два предложения.
2. **Формула или псевдокод.**
3. **Реализация.** Ключевые фрагменты кода, применённые оптимизации, команды компиляции.
4. **Корректность.** Эталон: numpy, PyTorch или собственная CPU-версия.
   Максимальная абсолютная и максимальная относительная ошибки.
5. **Обоснование метрик.** По каждой из четырёх метрик объяснить, что она измеряет
   и как рассчитана. Если значения метрики на отдельных размерах или версиях реализации
   выбиваются из общей картины, привести аргументы, с чем это связано. Это могут быть
   накладные расходы на распараллеливание, границы кэша, насыщение памяти,
   ограничения конкретного железа и так далее.
6. **Таблицы замеров.** Отдельная таблица по каждой метрике.
   Строки - размеры, столбцы - версии реализации.
   - Таблица 1. Время выполнения `t` (мс).
   - Таблица 2. Производительность GFLOPS.
   - Таблица 3. Пропускная способность GB/s.
   - Таблица 4. Ускорение относительно наивной реализации.
7. **Графики.** На графиках одна числовая ось:
   - Softmax задаётся парой `[M x N]`. На графике фиксируется число строк `M`,
     по оси X откладывается длина строки `N`. Дополнительно строится второй график
     для фиксированного `N` и меняющегося `M`, чтобы увидеть эффект числа строк.
   - Matmul задаётся тройкой `M x K x N`. На всех графиках используются только
     квадратные размеры `N x N x N`.

   На каждом графике отображаются все версии реализации.
   - График 1. Зависимость GFLOPS от размера задачи.
   - График 2. Зависимость GB/s от размера задачи.
   - График 3. Зависимость времени выполнения от размера задачи.
   - График 4. Масштабируемость OpenMP. Зависимость ускорения относительно
     однопоточной версии от числа потоков. Число потоков - от 1 до числа физических
     ядер машины. Отдельные линии - для размеров small, medium и large.
8. **Выводы.**
9. **Приложение.** Ссылка на репозиторий с исходным кодом.
